Politique de confidentialité — DisciplineX

Dernière mise à jour : 27 septembre 2026

1. Éditeur

Lompo Jérôme — développeur indépendant Contact : lompojerome80@gmail.com

2. Données collectées

DisciplineX ne collecte aucune donnée personnelle et ne transmet aucune information vers un serveur. L'application ne contient aucune dépendance d'analyse d'audience, aucun traceur publicitaire et ne demande aucune connexion.

3. Données stockées sur l'appareil

Toutes les données restent dans l'espace de stockage privé de l'application :

  • prénom et objectif principal saisis lors de l'onboarding ;
  • objectifs, habitudes, sessions de focus, alarmes, fenêtres de blocage ;
  • journaux d'activité quotidienne et score de discipline ;
  • durée d'utilisation hebdomadaire par application, lue dans les statistiques

d'usage du système, uniquement si vous avez accordé l'accès à l'utilisation ;

  • code de discipline : seule une empreinte salée (SHA-256, 10 000 itérations) et

son sel aléatoire sont conservés. Le code lui-même n'est jamais écrit sur le disque, ce qui permet de le changer ou de le supprimer à tout moment ;

  • réglages de l'application et préférences d'affichage ;
  • liste des applications sélectionnées pour le blocage (noms de paquets uniquement).

L'application est conçue pour être utilisée par la personne qui tient le téléphone. Un parent peut aussi l'installer sur le téléphone de son enfant et s'en servir pour l'aider à tenir ses engagements. Dans ce cas, le parent est la personne qui lit ces données sur l'appareil : l'application ne distingue pas les rôles, ne crée aucun compte, n'envoie aucune notification au parent et n'envoie rien à l'extérieur. Tout reste visible par quiconque ouvre l'application sur cet appareil.

Ces données sont chiffrées par le sandbox applicatif d'Android et ne sont pas lues par les autres applications.

4. Ce que le code de discipline protège

Lorsque vous définissez un code de discipline, il est demandé avant d'arrêter une session avant son terme, de terminer une session anticipativement, de débloquer une application, de retirer une application de la liste, de modifier les horaires de blocage et d'utiliser la sortie d'urgence.

Le code n'est jamais transmis, ni conservé en clair, ni lisible par une autre application. Le remplacer et le supprimer demandent tous deux le code actuel : l'application vérifie ce code avant d'appliquer le changement, et un code erroné laisse la protection inchangée. Ces deux actions restent disponibles depuis

dépend donc du code lui-même, et non d'un secret supplémentaire. Si le code est oublié, il faut effacer les données de l'application, ce qui supprime aussi la sessions et l'historique.

6. Service d'accessibilité

L'utilisation d'un service d'accessibilité est une décision sensible, car elle permet normalement de contrôler l'appareil. DisciplineX s'en sert dans un but strictement limité :

  • il lit uniquement le nom du paquet et le libellé de l'application au premier plan ;
  • il ne fait aucune capture d'écran, aucune lecture de contenu, aucune

écoute du micro, aucun accès à la localisation, aux contacts, aux SMS ou aux fichiers ;

  • il ne transmet rien à l'extérieur de l'appareil ;
  • il ne s'active que lorsque l'utilisateur l'a explicitement activé dans les

réglages Android, et il peut être désactivé à tout moment.

Pour plus de détails, consultez la déclaration d'usage de l'API Accessibility.

7. Suppression des données

  • Depuis l'application : *Profil & paramètres → Données → Effacer toutes mes

données* supprime le stockage local après confirmation explicite.

  • Depuis le système : *Réglages Android → Applications → DisciplineX →

Effacer les données*, ou désinstaller l'application.

Aucune donnée n'existe ailleurs que sur l'appareil : la suppression est donc immédiate et définitive.

8. Enfants

L'application n'est pas destinée aux enfants de moins de 13 ans et ne collecte aucune donnée personnelle, quel que soit l'âge de l'utilisateur.

9. Modifications

Toute mise à jour de cette politique sera publiée à la même adresse, avec une nouvelle date de mise à jour. Les versions antérieures sont conservées dans l'historique de version du projet.
